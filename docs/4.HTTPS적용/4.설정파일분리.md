## 현재 상황: 모든 설정이 한 파일에 집중된 문제

지금까지 설정된 내용만으로도 꽤 복잡해졌습니다. 현재 `/etc/nginx/conf.d/default.conf` 파일의 상태를 보면:

```
server {
    server_name nginx.jhcodeapi.com;
    location / {
        root /usr/share/nginx/nginx-basic-react/build;
        index index.html;
    }
    listen 443 ssl; # managed by Certbot
    ssl_certificate /etc/letsencrypt/live/nginx.jhcodeapi.com/fullchain.pem; # managed by Certbot
    ssl_certificate_key /etc/letsencrypt/live/nginx.jhcodeapi.com/privkey.pem; # managed by Certbot
    include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot
}

server {
    server_name admin.jhcodeapi.com;
    location / {
        root /usr/share/nginx/nginx-basic-nextjs/out;
        index index.html;
    }
    listen 443 ssl; # managed by Certbot
    ssl_certificate /etc/letsencrypt/live/admin.jhcodeapi.com/fullchain.pem; # managed by Certbot
    ssl_certificate_key /etc/letsencrypt/live/admin.jhcodeapi.com/privkey.pem; # managed by Certbot
    include /etc/letsencrypt/options-ssl-nginx.conf; # managed by Certbot
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem; # managed by Certbot
}

server {
    if ($host = nginx.jhcodeapi.com) {
        return 301 https://$host$request_uri;
    } # managed by Certbot
    listen 80;
    server_name nginx.jhcodeapi.com;
    return 404; # managed by Certbot
}

server {
    if ($host = admin.jhcodeapi.com) {
        return 301 https://$host$request_uri;
    } # managed by Certbot
    listen 80;
    server_name admin.jhcodeapi.com;
    return 404; # managed by Certbot
}

```

서비스가 커지면 커질수록 이 설정 파일도 점점 더 거대해질 것입니다. 한 파일에 너무 많은 코드가 담겨있으면 가독성이 떨어지고 유지보수가 어려워집니다.

## 왜 설정 파일을 분리해야 할까요?

### 1. **가독성 문제**

현재 상황에서도 이미 4개의 server 블록이 하나의 파일에 섞여 있어, 특정 도메인의 설정을 찾기 위해 파일을 위아래로 스크롤해야 합니다.

### 2. **유지보수의 어려움**

- `nginx.jhcodeapi.com` 설정만 수정하려고 해도 `admin.jhcodeapi.com` 설정을 실수로 건드릴 위험이 있습니다
- 하나의 서비스에 문제가 생겨도 전체 파일을 건드려야 하는 상황이 발생합니다

### 3. **협업 시 충돌 문제**

여러 개발자가 각각 다른 도메인을 담당할 때, 같은 `default.conf` 파일을 동시에 수정하면 Git merge conflict가 발생할 가능성이 높습니다.

### 4. **확장성 부족**

새로운 서비스가 추가될 때마다 이 파일은 계속 커지고, 결국 관리하기 어려운 거대한 파일이 됩니다.

## 기본적인 분리 방법 (원문에서 제시한 방법)

## 📈 더 나은 개선 방법 제안

위의 기본적인 분리 방법도 좋지만, 실무에서는 더 체계적인 접근이 필요합니다. 다음과 같은 개선사항들을 제안합니다:

### 1. **더 체계적인 디렉토리 구조**

```bash
# 기존 방법 개선
sudo mkdir -p /etc/nginx/conf.d/{sites-available,sites-enabled,snippets}

# sites-available: 모든 사이트 설정 저장
# sites-enabled: 활성화된 사이트만 (심링크 방식)
# snippets: 공통 설정 조각들

```

### 2. **공통 설정 분리로 중복 제거**

현재 각 도메인 설정에서 SSL 관련 설정이 중복되고 있습니다. 이를 공통으로 분리해보겠습니다:

**/etc/nginx/conf.d/snippets/ssl-common.conf**

```
# 공통 SSL 보안 설정
ssl_protocols TLSv1.2 TLSv1.3;
ssl_prefer_server_ciphers off;
ssl_session_cache shared:SSL:10m;
ssl_session_timeout 10m;

# 보안 헤더
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;

```

### 3. **개선된 개별 사이트 설정**

**/etc/nginx/conf.d/sites-available/nginx-jhcode.conf**

```
# React 애플리케이션 (nginx.jhcodeapi.com)

server {
    listen 443 ssl http2;
    server_name nginx.jhcodeapi.com;

    # SSL 인증서 (Certbot 관리)
    ssl_certificate /etc/letsencrypt/live/nginx.jhcodeapi.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nginx.jhcodeapi.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    # 공통 설정 적용
    include /etc/nginx/conf.d/snippets/ssl-common.conf;

    # React SPA 설정 (라우팅 지원)
    location / {
        root /usr/share/nginx/nginx-basic-react/build;
        index index.html;
        try_files $uri $uri/ /index.html;  # SPA 라우팅 지원
    }

    # 정적 파일 캐싱 최적화
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff|woff2)$ {
        root /usr/share/nginx/nginx-basic-react/build;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}

# HTTP to HTTPS 리다이렉트 (개선된 버전)
server {
    listen 80;
    server_name nginx.jhcodeapi.com;
    return 301 https://$server_name$request_uri;  # 더 깔끔한 리다이렉트
}

```

**/etc/nginx/conf.d/sites-available/admin-jhcode.conf**

```
# Next.js 관리자 애플리케이션 (admin.jhcodeapi.com)

server {
    listen 443 ssl http2;
    server_name admin.jhcodeapi.com;

    # SSL 인증서 (Certbot 관리)
    ssl_certificate /etc/letsencrypt/live/admin.jhcodeapi.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/admin.jhcodeapi.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    # 공통 설정 적용
    include /etc/nginx/conf.d/snippets/ssl-common.conf;

    # Next.js Static Export 설정
    location / {
        root /usr/share/nginx/nginx-basic-nextjs/out;
        index index.html;
        try_files $uri $uri/ $uri.html /index.html;  # Next.js 라우팅 지원
    }

    # Next.js _next 디렉토리 최적화
    location /_next/static/ {
        root /usr/share/nginx/nginx-basic-nextjs/out;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}

# HTTP to HTTPS 리다이렉트
server {
    listen 80;
    server_name admin.jhcodeapi.com;
    return 301 https://$server_name$request_uri;
}

```

### 4. **사이트 활성화 시스템**

**방법 1: include 방식 (기존 방법 개선)**

```
# /etc/nginx/conf.d/default.conf
include /etc/nginx/conf.d/sites-available/nginx-jhcode.conf;
include /etc/nginx/conf.d/sites-available/admin-jhcode.conf;

```

**방법 2: 심링크 방식 (더 유연함)**

```bash
# 사이트 활성화
sudo ln -s /etc/nginx/conf.d/sites-available/nginx-jhcode.conf /etc/nginx/conf.d/sites-enabled/

# 사이트 비활성화
sudo rm /etc/nginx/conf.d/sites-enabled/nginx-jhcode.conf

```

### 5. **완전한 설정 적용 과정**

```bash
# 1. 기존 default.conf 백업
sudo cp /etc/nginx/conf.d/default.conf /etc/nginx/conf.d/default.conf.backup

# 2. 디렉토리 구조 생성
sudo mkdir -p /etc/nginx/conf.d/{sites-available,snippets}

# 3. 공통 설정 파일 생성
sudo nano /etc/nginx/conf.d/snippets/ssl-common.conf

# 4. 개별 사이트 설정 파일 생성
sudo nano /etc/nginx/conf.d/sites-available/nginx-jhcode.conf
sudo nano /etc/nginx/conf.d/sites-available/admin-jhcode.conf

# 5. default.conf 수정 (include 추가)
sudo nano /etc/nginx/conf.d/default.conf

# 6. 설정 검사 및 적용
sudo nginx -t
sudo nginx -s reload

```

## 🎯 개선 후 얻는 이점

### ✅ **기존 방법 대비 추가 이점들**

1. **중복 코드 제거**: 공통 SSL 설정을 snippets로 분리하여 유지보수성 향상
2. **성능 최적화**: HTTP/2 활성화, 정적 파일 캐싱, SPA 라우팅 지원
3. **확장성**: 새로운 사이트 추가 시 템플릿처럼 활용 가능
4. **선택적 활성화**: 심링크 방식으로 사이트별 활성화/비활성화 가능

### ✅ **실무 관리 명령어들**

```bash
# 새 사이트 추가
sudo cp /etc/nginx/conf.d/sites-available/nginx-jhcode.conf /etc/nginx/conf.d/sites-available/api-jhcode.conf

sudo ln -s /etc/nginx/conf.d/sites-available/api-jhcode.conf /etc/nginx/conf.d/sites-enabled/

# 특정 사이트만 비활성화
sudo rm /etc/nginx/conf.d/sites-enabled/nginx-jhcode.conf

sudo tar -czf nginx-config-backup-$(date +%Y%m%d).tar.gz /etc/nginx/conf.d/

```
