# Nginx를 활용한 HTTPS 적용 완전 가이드

##  HTTPS를 적용시켜야 하는 이유

### 1. **보안적인 이유**
데이터를 서버와 주고 받을 때 암호화를 시켜서 통신을 한다. 암호화를 하지 않으면 누군가 중간에서 데이터를 가로채서 해킹할 수도 있다. 보안에 좋지 않다.

### 2. **사용자 이탈**
어떤 사이트에 들어갔는데 "안전하지 않음" 경고가 보인다면 왠지 믿음직스럽지 못한 사이트라고 생각할 것이다.

### 3. **SEO 및 검색 순위**
- Google은 2014년부터 HTTPS를 검색 순위 결정 요소로 사용
- HTTP 사이트는 검색 결과에서 불리한 위치에 배치

### 4. **브라우저 정책 및 최신 기능**
- 최신 브라우저들은 HTTP 사이트에서 위치 정보, 카메라, 마이크 등의 API 사용을 제한
- PWA(Progressive Web App) 기능도 HTTPS에서만 동작
- Service Worker, Push Notification 등 최신 웹 기술 사용 불가

### 5. **성능상의 이점**
- HTTP/2, HTTP/3는 HTTPS가 필수 요구사항
- 멀티플렉싱, 서버 푸시 등으로 더 빠른 페이지 로딩 속도 제공

---

## 🏗️ Nginx HTTPS 아키텍처

Nginx가 사용자(클라이언트)와 통신할 때, HTTPS를 활용해 암호화된 정보를 주고 받는 구조:

```
[클라이언트] ←--HTTPS/TLS--> [Nginx] ←--HTTP--> [Spring Boot App]
     |                         |                      |
  브라우저                   리버스 프록시           백엔드 서버
 (암호화 요청)              (SSL 종료점)            (일반 HTTP)
```
