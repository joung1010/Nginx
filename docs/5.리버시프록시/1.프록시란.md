# 프록시 서버와 네트워크 아키텍처 심화 가이드

## 프록시(Proxy)의 기본 개념

**프록시(Proxy)**란 '**중계(중간에서 연결해주는 것)**'의 의미를 가집니다.

**프록시 서버(Proxy Server)**는 **중간 역할을 해주는 서버**입니다. 클라이언트(사용자)와 서버가 직접 통신하지 않고 **중간 역할을 하는 서버**를 거쳐서 통신을 합니다. 여기서 **중간 역할을 하는 서버**를 **프록시 서버(Proxy Server)**라고 부릅니다.

그래서 클라이언트가 직접 WAS와 통신하지 않고 중간에 nginx를 거쳐서 서로 통신을 하는 리버스 프록시의 역할도 nginx는 가능합니다. 그래서 하나의 EC2 혹은 서버에 프록시 서버와 WAS서버를 같이 구성할 수 있고 따로 구성할 수도 있습니다.

## 네트워크 계층 관점에서 본 프록시

### OSI 7계층에서의 프록시 동작

```
[클라이언트] ←→ [프록시 서버] ←→ [실제 서버]
     ↓              ↓              ↓
Application    Application    Application
Presentation   Presentation   Presentation  
Session        Session        Session
Transport      Transport      Transport     ← TCP 연결 종료/시작
Network        Network        Network       ← IP 라우팅 처리
Data Link      Data Link      Data Link
Physical       Physical       Physical
```

**중요한 점**: 프록시 서버는 **TCP 연결을 두 번 처리**합니다.
- **연결 1**: 클라이언트 ↔ 프록시 서버
- **연결 2**: 프록시 서버 ↔ 실제 서버

이는 **TCP 핸드셰이크가 두 번 발생**함을 의미하며, 이로 인해 지연시간(latency)이 추가되지만 중간에서 트래픽을 제어할 수 있는 장점을 얻습니다.

### IP 주소와 포트 관점에서의 변화

**직접 연결 시:**
```
클라이언트(192.168.1.100:54321) → 서버(203.123.45.67:80)
```

**프록시를 통한 연결 시:**
```
클라이언트(192.168.1.100:54321) → 프록시(10.0.0.50:80)
프록시(10.0.0.50:34567) → 실제서버(192.168.10.100:8080)
```

실제 서버는 클라이언트의 실제 IP를 모르고 프록시 서버의 IP만 알게 됩니다. 이때 클라이언트의 실제 정보를 전달하기 위해 **HTTP 헤더**를 활용합니다:

```http
X-Forwarded-For: 192.168.1.100
X-Real-IP: 192.168.1.100
X-Forwarded-Proto: https
```

## 포워드 프록시(Forward Proxy) 심화

### 네트워크 토폴로지 관점

```
[내부망]                    [DMZ]                [외부 인터넷]
클라이언트들 → 포워드 프록시 → 방화벽 → 인터넷 서비스들
(사내 PC)     (보안 정책)    (경계)    (웹사이트들)
```

**보내려고 하는 요청**을 **관리** 또는 **보안 처리**를 위한 용도로 사용하는 서버를 **포워드 프록시(Forward Proxy) 서버**라고 합니다.

### 포워드 프록시의 심화 기능들

#### 1. **컨텐츠 필터링 (Content Filtering)**
```bash
# 예시: 회사에서 특정 도메인 차단
blocked_domains = ["facebook.com", "youtube.com", "openai.com"]
if request.host in blocked_domains:
    return HTTP_403_FORBIDDEN
```

#### 2. **캐싱 메커니즘 (Caching)**
포워드 프록시는 **HTTP 캐시 헤더**를 분석하여 자주 요청되는 리소스를 로컬에 저장합니다:

```http
# 프록시가 캐시 가능 여부 판단
Cache-Control: max-age=3600, public
ETag: "abc123def456"
Last-Modified: Wed, 21 Oct 2015 07:28:00 GMT
```

#### 3. **대역폭 제어 (Bandwidth Shaping)**
```nginx
# nginx에서 대역폭 제한 예시
location / {
    limit_rate 100k;  # 100KB/s로 제한
    proxy_pass http://external_server;
}
```

#### 4. **인증 및 로깅**
```
[접속 로그 예시]
2025-09-05 10:30:15 | 192.168.1.100 | GET | https://github.com | ALLOWED
2025-09-05 10:30:20 | 192.168.1.101 | GET | https://facebook.com | BLOCKED
```

### 포워드 프록시 구현 예시 (Nginx)

```nginx
# 포워드 프록시 설정
server {
    listen 8080;
    resolver 8.8.8.8;  # DNS 서버 설정
    
    location / {
        # 클라이언트가 요청한 실제 URL로 프록시
        proxy_pass $scheme://$http_host$request_uri;
        
        # 차단된 사이트 필터링
        if ($http_host ~* "(facebook|youtube)\.com") {
            return 403 "Access Denied by Company Policy";
        }
        
        # 로깅
        access_log /var/log/nginx/forward_proxy.log;
    }
}
```

## 리버스 프록시(Reverse Proxy) 심화

### 네트워크 아키텍처 관점

```
[인터넷] → [리버스 프록시] → [내부 서버들]
          (Load Balancer)    (Web Server Farm)
             └─ SSL 종료
             └─ 캐싱        
             └─ 압축
             └─ 보안 필터링
```

**들어오는 요청**을 **관리** 또는 **보안 처리**를 하기 위한 용도로 사용하는 서버를 **리버스 프록시(Reverse Proxy) 서버**라고 합니다.

### 리버스 프록시의 고급 기능들

#### 1. **SSL/TLS 터미네이션 (SSL Termination)**

```nginx
server {
    listen 443 ssl http2;
    
    # SSL 인증서 설정
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/private.key;
    
    # SSL 세션 최적화
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;
    
    # 백엔드로는 HTTP로 전달 (SSL 부하 제거)
    location / {
        proxy_pass http://backend_servers;
        
        # 백엔드에 원본 정보 전달
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Host $host;
    }
}
```

#### 2. **로드 밸런싱 알고리즘**

```nginx
# 백엔드 서버 풀 정의
upstream backend_servers {
    # 라운드 로빈 (기본값)
    server 192.168.1.10:8080 weight=3;
    server 192.168.1.11:8080 weight=2;
    server 192.168.1.12:8080 weight=1;
    
    # 헬스 체크
    server 192.168.1.13:8080 backup;  # 백업 서버
    
    # 세션 유지 (IP 해시)
    ip_hash;
    
    # 최소 연결 수 기반
    # least_conn;
}
```

**로드 밸런싱 알고리즘 종류:**
- **Round Robin**: 순차적으로 분배
- **Weighted Round Robin**: 가중치 기반 분배
- **Least Connections**: 연결 수가 가장 적은 서버로
- **IP Hash**: 클라이언트 IP 기반 고정 분배
- **Least Time**: 응답 시간이 가장 빠른 서버로

#### 3. **캐싱 및 성능 최적화**

```nginx
# 프록시 캐싱 설정
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m max_size=10g inactive=60m;

server {
    location / {
        proxy_pass http://backend_servers;
        
        # 캐싱 설정
        proxy_cache my_cache;
        proxy_cache_valid 200 302 10m;
        proxy_cache_valid 404 1m;
        
        # 캐시 키 설정
        proxy_cache_key "$scheme$request_method$host$request_uri";
        
        # 캐시 상태 헤더 추가
        add_header X-Cache-Status $upstream_cache_status;
    }
    
    # 정적 파일 압축
    location ~* \.(css|js|png|jpg|jpeg|gif|svg)$ {
        gzip on;
        gzip_types text/css application/javascript image/svg+xml;
        proxy_pass http://backend_servers;
    }
}
```

#### 4. **보안 기능들**

```nginx
# Rate Limiting (요청 수 제한)
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

server {
    # DDoS 방어
    limit_req zone=api burst=20 nodelay;
    
    # 보안 헤더 추가
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    
    # 악성 요청 필터링
    location / {
        # SQL Injection 패턴 차단
        if ($args ~* "(union|select|insert|delete|drop|create|alter)") {
            return 403 "Malicious request detected";
        }
        
        # User-Agent 기반 봇 차단
        if ($http_user_agent ~* "(bot|crawler|spider|wget|curl)") {
            return 403 "Bot access denied";
        }
        
        proxy_pass http://backend_servers;
    }
}
```

## 리버스 프록시 활용 이유 - 네트워크 관점에서

### 1. **네트워크 보안 경계 설정**

```
[외부 인터넷] → [DMZ - 리버스 프록시] → [내부망 - 애플리케이션 서버들]
                      ↓
                  - WAF (Web Application Firewall)
                  - SSL 터미네이션
                  - 로그 수집
                  - 침입 탐지
```

만약 리버스 프록시 서버를 사용하지 않고 직접적으로 들어오는 요청을 백엔드 서버가 바로 받아 처리하는 식으로 구성하면 보안적으로 문제되는 경우가 많습니다.

### 2. **트래픽 제어 및 QoS (Quality of Service)**

```nginx
# 서비스별 차등 처리
location /api/premium/ {
    limit_req zone=premium burst=100;  # 프리미엄 사용자
    proxy_pass http://high_performance_servers;
}

location /api/free/ {
    limit_req zone=free burst=10;      # 무료 사용자
    proxy_pass http://basic_servers;
}
```

### 3. **장애 격리 (Fault Isolation)**

```nginx
upstream backend {
    server app1:8080 max_fails=3 fail_timeout=30s;
    server app2:8080 max_fails=3 fail_timeout=30s;
    server app3:8080 backup;  # 장애 시 자동 전환
}
```

### 4. **모니터링 및 관찰 가능성 (Observability)**

```nginx
# 상세 로그 설정
log_format detailed '$remote_addr - $remote_user [$time_local] '
                   '"$request" $status $body_bytes_sent '
                   '"$http_referer" "$http_user_agent" '
                   'rt=$request_time uct="$upstream_connect_time" '
                   'uht="$upstream_header_time" urt="$upstream_response_time"';

access_log /var/log/nginx/detailed.log detailed;
```

## 실제 운영 환경에서의 프록시 아키텍처

### 다중 계층 프록시 구조

```
[클라이언트]
    ↓
[CDN (Cloudflare, AWS CloudFront)]  ← 글로벌 엣지 캐싱
    ↓
[Application Load Balancer]         ← AWS ALB, NGINX Plus
    ↓
[리버스 프록시 (NGINX)]             ← SSL 터미네이션, 캐싱
    ↓
[애플리케이션 서버들]               ← 실제 비즈니스 로직
```

### 마이크로서비스 환경에서의 프록시

```nginx
# API Gateway 역할
location /user-service/ {
    proxy_pass http://user-service-cluster/;
}

location /order-service/ {
    proxy_pass http://order-service-cluster/;
}

location /payment-service/ {
    proxy_pass http://payment-service-cluster/;
}
```

## 성능 최적화 고려사항

### 1. **연결 풀링 (Connection Pooling)**

```nginx
upstream backend {
    server app1:8080;
    
    # 연결 유지 설정
    keepalive 32;          # 32개 연결 유지
    keepalive_requests 100; # 연결당 최대 요청 수
    keepalive_timeout 60s;  # 연결 유지 시간
}

server {
    location / {
        proxy_pass http://backend;
        
        # HTTP/1.1 사용 (연결 재사용)
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
```

### 2. **버퍼링 최적화**

```nginx
# 프록시 버퍼 설정
proxy_buffering on;
proxy_buffer_size 128k;
proxy_buffers 4 256k;
proxy_busy_buffers_size 256k;

# 대용량 파일 처리
client_max_body_size 100M;
proxy_read_timeout 300s;
proxy_send_timeout 300s;
```

이렇게 네트워크 관점에서 프록시를 이해하면, 단순한 중계 서버가 아닌 **네트워크 아키텍처의 핵심 구성요소**로서 보안, 성능, 확장성을 모두 책임지는 중요한 역할을 한다는 것을 알 수 있습니다.
