# Nginx Upstream 블록 설정 옵션 완전 가이드

## 🎯 Upstream 블록 기본 구조

```nginx
upstream backend_name {
    # 로드 밸런싱 방법 (하나만 선택)
    [method];
    
    # 서버 목록 (필수)
    server address [parameters];
    server address [parameters];
    
    # 연결 최적화 옵션들
    [connection_options];
    
    # 기타 전역 옵션들
    [global_options];
}
```

---

## 🔄 로드 밸런싱 방법 옵션 (택 1)

### 기본 (Round Robin) - 설정 없음

```nginx
upstream backend {
    # 아무것도 설정하지 않으면 기본 라운드 로빈
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
}
```

### `ip_hash` - IP 기반 고정 분배

```nginx
upstream backend {
    ip_hash;  # 클라이언트 IP 해시로 서버 고정
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
}
```

### `least_conn` - 최소 연결 기반

```nginx
upstream backend {
    least_conn;  # 연결 수가 가장 적은 서버로 분배
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
}
```

### `hash` - 사용자 정의 키 기반 (Nginx Plus)

```nginx
upstream backend {
    hash $request_uri;  # URL 기반 해시
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
}
```

## 🖥️ Server 설정 옵션

### 기본 서버 정의

```nginx
upstream backend {
    server 192.168.1.10:8080;                    # 기본 서버
    server 192.168.1.11:8080 [parameters];       # 옵션 포함 서버
}
```

### Server Parameters (개별 서버 옵션)

#### `weight=number` - 가중치

```nginx
upstream backend {
    server 10.0.1.10:8080 weight=3;  # 3배 많은 요청 처리
    server 10.0.1.11:8080 weight=2;  # 2배 많은 요청 처리
    server 10.0.1.12:8080 weight=1;  # 기본 가중치
}
```

#### `max_fails=number` - 최대 실패 횟수

```nginx
upstream backend {
    server 10.0.1.10:8080 max_fails=3;   # 3번 실패 시 비활성화
    server 10.0.1.11:8080 max_fails=5;   # 5번 실패 시 비활성화
}
```

#### `fail_timeout=time` - 실패 타임아웃

```nginx
upstream backend {
    server 10.0.1.10:8080 fail_timeout=30s;  # 30초간 비활성화
    server 10.0.1.11:8080 fail_timeout=60s;  # 60초간 비활성화
}
```

#### `backup` - 백업 서버

```nginx
upstream backend {
    server 10.0.1.10:8080;           # 주 서버
    server 10.0.1.11:8080;           # 주 서버
    server 10.0.1.12:8080 backup;    # 백업 서버 (주 서버 모두 실패시만 사용)
}
```

#### `down` - 서버 비활성화

```nginx
upstream backend {
    server 10.0.1.10:8080;           # 활성 서버
    server 10.0.1.11:8080 down;      # 비활성화된 서버 (유지보수용)
}
```

#### `slow_start=time` - 서버 점진적 복구 (Nginx Plus)

```nginx
upstream backend {
    server 10.0.1.10:8080 slow_start=30s;  # 30초에 걸쳐 점진적 트래픽 증가
}
```

#### `max_conns=number` - 최대 동시 연결 (Nginx Plus)

```nginx
upstream backend {
    server 10.0.1.10:8080 max_conns=100;   # 최대 100개 동시 연결
}
```

## 🔗 연결 최적화 옵션

### `keepalive` - 연결 풀 유지

```nginx
upstream backend {
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
    
    keepalive 32;  # worker당 32개 연결 유지
}
```

### `keepalive_requests` - 연결당 최대 요청 수

```nginx
upstream backend {
    server 10.0.1.10:8080;
    
    keepalive 32;
    keepalive_requests 100;  # 연결당 최대 100개 요청 처리 후 새 연결
}
```

### `keepalive_timeout` - 연결 유지 시간

```nginx
upstream backend {
    server 10.0.1.10:8080;
    
    keepalive 32;
    keepalive_timeout 60s;  # 60초간 연결 유지
}
```

## 🌐 공유 메모리 및 고급 옵션 (Nginx Plus)

### `zone` - 공유 메모리 영역

```nginx
upstream backend {
    zone backend_zone 64k;  # 64KB 공유 메모리 할당
    
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
}
```

### `queue` - 요청 대기열 (Nginx Plus)

```nginx
upstream backend {
    server 10.0.1.10:8080 max_conns=50;
    
    queue 100 timeout=70s;  # 최대 100개 요청 대기, 70초 타임아웃
}
```

## 📋 완전한 예시: 모든 옵션 조합

```nginx
upstream production_backend {
    # 로드 밸런싱 방법
    least_conn;
    
    # 서버 목록 (각각 다른 옵션 적용)
    server 10.0.1.10:8080 weight=3 max_fails=2 fail_timeout=30s;
    server 10.0.1.11:8080 weight=2 max_fails=3 fail_timeout=45s;
    server 10.0.1.12:8080 weight=1 max_fails=1 fail_timeout=20s;
    server 10.0.1.13:8080 backup;
    server 10.0.1.14:8080 down;  # 유지보수 중
    
    # 연결 최적화
    keepalive 32;
    keepalive_requests 100;
    keepalive_timeout 60s;
    
    # Nginx Plus 전용 (있는 경우)
    # zone production 64k;
    # queue 50 timeout=60s;
}
```

## 🎮 실제 사용 시나리오별 설정

### 시나리오 1: 세션 유지가 중요한 경우

```nginx
upstream session_backend {
    ip_hash;  # 같은 클라이언트는 항상 같은 서버로
    
    server app1.example.com:8080;
    server app2.example.com:8080;
    server app3.example.com:8080;
}
```

### 시나리오 2: 서버 성능이 다른 경우

```nginx
upstream mixed_backend {
    server high-spec.example.com:8080 weight=5;   # 고성능 서버
    server mid-spec.example.com:8080 weight=3;    # 중간 성능 서버
    server low-spec.example.com:8080 weight=1;    # 저성능 서버
    server backup.example.com:8080 backup;       # 백업 서버
}
```

### 시나리오 3: 고가용성 중심 설정

```nginx
upstream ha_backend {
    least_conn;
    
    server primary1.example.com:8080 max_fails=2 fail_timeout=10s;
    server primary2.example.com:8080 max_fails=2 fail_timeout=10s;
    server secondary1.example.com:8080 max_fails=1 fail_timeout=5s backup;
    
    keepalive 16;  # 연결 효율성도 고려
}
```
