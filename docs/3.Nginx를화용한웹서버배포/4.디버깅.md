## Nginx 디버깅

### 기본적인 문법 검사

```bash
sudo nginx -t
```

**중요한 점:** Nginx의 문법 검사는 **설정 파일의 구문(syntax)만 검사**하지, **실제 파일이나 경로의 존재 여부는 확인하지 않습니다**.

### 📁 경로 오타 예시 분석

**정상적인 설정:**

```bash
location / {
    root   /usr/share/nginx/html;
    index  hello.html;
}
```

**오타가 발생한 설정:**

```bash
location / {
    root   /usr/share/nginx/htlm;    *# html → htlm (오타!)*
    index  hello.html;
}
```

**문법 검사 결과:**

```bash
$ sudo nginx -t
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

이렇게 오타가 발생했을 때도 문법 검사 명령어는 **정상적으로 성공을 확인**할 수 있다.

**왜 그럴까?**

- `nginx -t`는 **설정 파일의 문법 구조**만 검사 (중괄호, 세미콜론, 지시문 이름 등)
- **디렉토리나 파일의 실제 존재 여부는 runtime에만 확인**됨
- 설정 구문 자체는 올바르기 때문에 문법 검사를 통과

### 🛠️ 단계별 디버깅 프로세스

### **Step 1: 기본 상태 확인**

```bash
*# 1. 서비스 상태 확인*
sudo systemctl status nginx

*# 2. 포트 바인딩 확인*  
sudo netstat -tlnp | grep nginx
*# 또는*
sudo ss -tlnp | grep nginx

*# 출력 예시*
tcp  0  0  0.0.0.0:80    0.0.0.0:*  LISTEN  1234/nginx: master
```

### **Step 2: 설정 검증**

```bash
*# 1. 문법 검사*
sudo nginx -t

*# 2. 전체 설정 확인 (실제 적용되는 설정)*
sudo nginx -T | less

*# 3. 특정 server 블록만 확인*
sudo nginx -T | grep -A 20 -B 5 "server {"
```

### **Step 3: 파일 시스템 검증**

```bash
*# 1. 웹 루트 디렉토리 존재 확인*
ls -la /usr/share/nginx/html/

*# 2. 파일 권한 확인*
ls -la /usr/share/nginx/html/index.html

*# 3. nginx 사용자 권한 확인*
sudo -u nginx cat /usr/share/nginx/html/index.html
```

### **Step 4: 실시간 디버깅**

```bash
*# 터미널 1: 에러 로그 모니터링*
sudo tail -f /var/log/nginx/error.log

*# 터미널 2: 액세스 로그 모니터링*  
sudo tail -f /var/log/nginx/access.log

*# 터미널 3: 테스트 요청 보내기*
curl -v http://localhost/
```

### 🔧 일반적인 문제들과 해결방법

### **1. 경로 오타 문제**

```bash
*# 🔴 문제: root 경로 오타*
root /usr/share/nginx/htlm;

*# 🔍 에러 로그에서 확인:# "/usr/share/nginx/htlm/index.html" is not found# ✅ 해결: 올바른 경로로 수정*
root /usr/share/nginx/html;
```

### **2. 파일 권한 문제**

```bash
*# 🔍 권한 확인*
ls -la /usr/share/nginx/html/

*# 🔴 문제 예시: 권한 부족*
-rw------- 1 root root 612 Aug 31 12:00 index.html

*# ✅ 해결: 적절한 권한 설정*
sudo chown nginx:nginx /usr/share/nginx/html/index.html
sudo chmod 644 /usr/share/nginx/html/index.html
```

### **3. 포트 충돌 문제**

```bash
*# 🔍 포트 사용 상태 확인*
sudo netstat -tlnp | grep :80

*# 🔴 문제: 다른 서비스가 80번 포트 사용 중*
tcp  0  0  0.0.0.0:80  0.0.0.0:*  LISTEN  5678/apache2

*# ✅ 해결: 충돌 서비스 중지 또는 다른 포트 사용*
sudo systemctl stop apache2
*# 또는*
listen 8080;  *# nginx 설정에서 다른 포트 사용*
```

### 🎯 실전 디버깅 시나리오

**문제 상황:** 브라우저에서 403 Forbidden 에러 발생

**디버깅 과정:**

```bash
*# 1. 에러 로그 확인*
sudo tail -10 /var/log/nginx/error.log
*# 출력: "directory index of "/usr/share/nginx/html/" is forbidden"# 2. 디렉토리 권한 확인*
ls -la /usr/share/nginx/html/
*# 출력: drwx------ 2 root root 4096 Aug 31 12:00 .# 3. 권한 수정*
sudo chmod 755 /usr/share/nginx/html/
sudo chown -R nginx:nginx /usr/share/nginx/html/

*# 4. 설정 리로드*
sudo nginx -s reload

*# 5. 재테스트*
curl http://localhost/
```

이런 방식으로 **단계적으로 문제를 좁혀가며 디버깅**하면 대부분의 Nginx 문제를 해결할 수 있습니다!
