## 한 서버에서 다른 도메인을 가진 여러 웹 사이트를 배포 하려면!?

일반적으로 배포된 웹 사이트를 보면 **IP 주소**로 접근하지 않고 **도메인 주소**로 접근을 한다. 왜냐하면 IP 주소는 기억하기 어렵기 때문이다. 그래서 대부분의 웹 사이트는 도메인 주소를 가지고 있다.

### 🌐 도메인과 IP 연결 메커니즘

도메인을 연결시킬 때 **도메인 주소**와 **EC2 IP 주소**를 연결시킨다. 그러면 도메인 주소로 접근했을 때 IP 주소로 변환해서 접근을 할 수 있게 된다.

**DNS 해석 과정:**

```
사용자 입력: nginx.jhcodeapi.com
     ↓
DNS 서버 조회: nginx.jhcodeapi.com → 13.209.26.55
     ↓  
실제 요청: http://13.209.26.55/
     ↓
Nginx 서버에 도달
```

즉, 주소창에 [nginx.jhcodeapi.com](http://nginx.jhcodeapi.com/)로 입력하는 순간, 지정된 IP주소로 변환해서 요청을 보내게 된다. 그럼 우리가 배웠던 그대로 Nginx가 웹 사이트에 필요한 파일(HTML, CSS, JS, 이미지 파일 등)로 응답해준다.

### 🤔 다중 도메인 배포 문제

> 그렇다면 하나의 서버에서 두 종류의 웹 사이트를 배포하고 싶다면 어떻게 해야할까?
>

두 종류의 웹 사이트를 배포한다고 하더라도, 각각의 웹 사이트마다 도메인을 가지고 있는 경우가 일반적이다. 예를 들어 [nginx.jhcodeapi.com](http://nginx.jhcodeapi.com/) 이라는 주소가 있고 관리자용 도메인은 [admin.jhpark.kr](http://admin.jhpark.kr/) 이라는 도메인으로 접근하게 만들고 싶을 수 있다.

### 🔄 동일한 IP, 다른 도메인의 딜레마

```
그런데 위에서 잠깐 얘기했다시피 도메인 주소는 IP 주소와 연결시키는 방식이다. 그렇다면:

**DNS 설정:**

`nginx.jhcodeapi.com  →  13.209.26.55 (EC2 IP)
admin.jhpark.kr      →  13.209.26.55 (동일한 EC2 IP)`
```

**실제 요청 흐름:**

```
사용자가 nginx.jhcodeapi.com 입력
     ↓
DNS: nginx.jhcodeapi.com → 13.209.26.55
     ↓
HTTP 요청: GET / HTTP/1.1
Host: nginx.jhcodeapi.com    👈 중요! Host 헤더에 원본 도메인 정보
     ↓
EC2 Nginx 서버 (13.209.26.55)

동시에...

사용자가 admin.jhpark.kr 입력  
     ↓
DNS: admin.jhpark.kr → 13.209.26.55
     ↓
HTTP 요청: GET / HTTP/1.1
Host: admin.jhpark.kr        👈 다른 Host 헤더!
     ↓
동일한 EC2 Nginx 서버 (13.209.26.55)
```

[nginx.jhcodeapi.com](http://nginx.jhcodeapi.com/)의 도메인도 EC2의 IP 주소(ex. 13.209.26.55)에 연결을 시키고, [admin.jhpark.kr](http://admin.jhpark.kr/)의 도메인도 EC2의 IP 주소(ex. 13.209.26.55.)에 연결을 시키게 된다. 즉, 어떤 도메인 주소로 요청이 들어오던 EC2의 Nginx로 요청이 들어온다는 뜻이다.

**Nginx의 입장에서는 nginx.jhcodeapi.com로 요청이 들어온 거랑 admin.jhpark.kr로 요청이 들어온 거랑 구별해서 웹 사이트를 보여줄 수 있어야 한다.**

### 🎯 Nginx의 Virtual Host 해결책

Nginx는 **HTTP Host 헤더**를 통해 어떤 도메인으로 요청이 들어왔는지 구별할 수 있습니다.

### **실제 HTTP 요청 분석:**

**nginx.jhcodeapi.com 요청:**

```
GET / HTTP/1.1
Host: nginx.jhcodeapi.com    👈 Nginx가 이 값으로 구별!
User-Agent: Mozilla/5.0...
Accept: text/html...
```

**admin.jhpark.kr 요청:**

```
GET / HTTP/1.1  
Host: admin.jhpark.kr        👈 다른 Host 헤더 값!
User-Agent: Mozilla/5.0...
Accept: text/html...
```

### **Nginx server_name 매칭:**

nginx

```bash
*# 첫 번째 웹사이트 설정*
server {
    listen 80;
    server_name nginx.jhcodeapi.com;    *# Host 헤더와 매칭*
    
    location / {
        root /var/www/main-site;
        index index.html;
    }
}

*# 두 번째 웹사이트 설정*  
server {
    listen 80;
    server_name admin.jhpark.kr;        *# 다른 Host 헤더와 매칭*
    
    location / {
        root /var/www/admin-site;       *# 다른 디렉토리!*
        index index.html;
    }
}
```

### 🔍 요청 처리 과정 상세 분석

**1단계: 요청 도착**

```
클라이언트 → nginx.jhcodeapi.com 요청 → EC2 (13.209.26.55:80)
클라이언트 → admin.jhpark.kr 요청 → EC2 (13.209.26.55:80)
```

**2단계: Nginx의 server 블록 선택**

```
Nginx 내부 로직:
1. 들어온 요청의 Host 헤더 확인
2. server_name과 매칭되는 server 블록 찾기
3. 매칭된 server 블록의 설정 적용
4. 해당 root 디렉토리에서 파일 응답
```

**3단계: 파일 시스템 매핑**

```
nginx.jhcodeapi.com 요청:
Host: nginx.jhcodeapi.com → server_name nginx.jhcodeapi.com 매칭
→ root /var/www/main-site → /var/www/main-site/index.html 응답

admin.jhpark.kr 요청:  
Host: admin.jhpark.kr → server_name admin.jhpark.kr 매칭
→ root /var/www/admin-site → /var/www/admin-site/index.html 응답
```

### 📊 다중 도메인 관리 방식

### **방식 1: 개별 설정 파일**

```bash
/etc/nginx/conf.d/
├── main-site.conf          *# nginx.jhcodeapi.com 설정*
├── admin-site.conf         *# admin.jhpark.kr 설정*  
└── api-site.conf           *# api.jhpark.kr 설정*
```

### **방식 2: 단일 설정 파일**

```bash
*# /etc/nginx/conf.d/all-sites.conf*
server {
    listen 80;
    server_name nginx.jhcodeapi.com;
    root /var/www/main-site;
    *# ... 기타 설정*
}

server {
    listen 80;
    server_name admin.jhpark.kr;  
    root /var/www/admin-site;
    *# ... 기타 설정*
}
```

### 🚀 실제 구현 예시

**디렉토리 구조:**

```bash
/var/www/
├── main-site/              *# 메인 웹사이트*
│   ├── index.html
│   ├── css/
│   └── js/
├── admin-site/             *# 관리자 웹사이트*
│   ├── index.html  
│   ├── css/
│   └── js/
└── api-docs/               *# API 문서 사이트*
    ├── index.html
    └── assets/
```

**Nginx 설정:**

nginx

```bash
*# 메인 웹사이트*
server {
    listen 80;
    server_name nginx.jhcodeapi.com www.nginx.jhcodeapi.com;
    
    location / {
        root /var/www/main-site;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}

*# 관리자 웹사이트*
server {
    listen 80;
    server_name admin.jhpark.kr;
    
    location / {
        root /var/www/admin-site;
        index index.html;
        
        *# 🔒 관리자 사이트 접근 제한*
        allow 203.241.132.0/24;  *# 회사 IP 대역만 허용*
        deny all;
    }
}

*# API 문서 사이트*
server {
    listen 80;
    server_name docs.jhpark.kr;
    
    location / {
        root /var/www/api-docs;
        index index.html;
    }
}
```

이렇게 **하나의 Nginx 서버에서 Host 헤더를 기반으로 여러 도메인을 구별**하여 각각 다른 웹사이트를 서빙할 수 있습니다!
