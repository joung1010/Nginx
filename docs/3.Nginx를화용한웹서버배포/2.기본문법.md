## Nginx 기본 문법 해석하기

Nginx를 설치하고 실행시키면 기본 웹 페이지가 뜬다. 하지만 아래 웹 페이지가 아닌 우리가 직접 만든 웹 페이지를 띄우고 싶을 것이다. 그러려면 Nginx의 기본적인 문법을 어느 정도 알고 있어야, 설정값을 직접 수정해서 응용할 수 있다.

### 📁 Nginx의 설정 파일 위치

### 1. `/etc/nginx/nginx.conf`

- Nginx에서 **가장 근본이 되는 설정 파일(루트 설정 파일)**
- **전역적으로 설정되어야 하는 내용**이 포함되어 있다:
    - **워커 프로세스 개수**: CPU 코어 수에 맞춰 최적화
    - **로그 저장 위치**: 액세스 로그, 에러 로그 경로 설정
    - **전역 보안 설정**: 기본 헤더, 제한 사항 등
    - **include 지시문**: 다른 설정 파일들을 포함시키는 역할

```bash
*# nginx.conf 주요 설정 예시*
worker_processes auto;                    *# CPU 코어 수만큼 워커 생성*
worker_connections 1024;                  *# 워커당 최대 연결 수*

http {
    include /etc/nginx/mime.types;        *# 파일 타입 정의 포함*
    include /etc/nginx/conf.d/*.conf;     *# 개별 사이트 설정들 포함*
}
```

### 2. `~~/etc/nginx/conf.d/default.conf~~` ← **최신 Nginx에서는 존재하지 않음!**

### 🚨 최신 Nginx에서 default.conf 파일이 없는 이유

### **배경: 설정 관리 방식의 변화**

최신 Nginx 설치에서 `/etc/nginx/conf.d/default.conf` 파일이 존재하지 않는 것은 의도적인 변화입니다. 이는 여러 설정 관리 방식이 혼재하면서 발생한 혼란을 줄이기 위한 조치 [Stack Overflow](https://stackoverflow.com/questions/41303885/nginx-do-i-really-need-sites-available-and-sites-enabled-folders)[Server Fault](https://serverfault.com/questions/527630/difference-in-sites-available-vs-sites-enabled-vs-conf-d-directories-nginx)입니다.

### **1. 배포판별 차이점**

**Debian/Ubuntu 계열:**

- 전통적으로 `sites-available` / `sites-enabled` 디렉토리 구조 사용
- Apache의 설정 방식을 모방한 심볼릭 링크 기반 관리
- 이 구조는 Debian이 Apache 설정을 모방하기 위해 만든 관례이며, nginx 자체의 기본 구조는 아닙니다 [Server Fault](https://serverfault.com/questions/527630/difference-in-sites-available-vs-sites-enabled-vs-conf-d-directories-nginx)[Stack Overflow](https://stackoverflow.com/questions/17413526/nginx-missing-sites-available-directory)

**CentOS/RHEL/Amazon Linux:**

- `conf.d` 디렉토리만 사용하는 단순한 구조
- CentOS 7에서 nginx를 설치하면 conf.d 디렉토리는 비어있고 nginx.conf 파일만 존재합니다 [Stack Overflow](https://stackoverflow.com/questions/17413526/nginx-missing-sites-available-directory)[Stack Overflow](https://stackoverflow.com/questions/56929815/nginx-default-conf-missing-on-centos-7)

**공식 nginx.org 패키지:**

- 공식 nginx.org에서 제공하는 패키지는 sites-available/sites-enabled 구조를 사용하지 않습니다 [Nginx - Do I really need sites-available and sites-enabled folders? - Stack Overflow](https://stackoverflow.com/questions/41303885/nginx-do-i-really-need-sites-available-and-sites-enabled-folders)

### **2. 현대적 설정 관리 접근법**

**이전 방식 (복잡함):**

```bash
*# 구식 접근법 - 3개 디렉토리 혼재*
/etc/nginx/
├── nginx.conf              *# 메인 설정*
├── conf.d/                 *# 추가 설정 파일들*
│   └── default.conf
├── sites-available/        *# 사용 가능한 사이트들*
│   └── mysite.conf
└── sites-enabled/          *# 활성화된 사이트들 (심볼릭 링크)*
    └── mysite.conf -> ../sites-available/mysite.conf
```

**현재 권장 방식 (단순함):**

bash

```bash
*# 현대적 접근법 - 2개 디렉토리만 사용*
/etc/nginx/
├── nginx.conf              *# 메인 설정 + 기본 server 블록*
└── conf.d/                 *# 추가 사이트 설정들*
    ├── api.conf
    ├── blog.conf
    └── admin.conf
```

### **3. 설정 관리 철학의 변화**

**컨테이너 시대의 영향:**

- 최근에는 서버가 종종 단일 웹사이트/서비스만 제공하는 일시적 컨테이너로 나타나므로, nginx.conf에 직접 포함해도 가독성 손실이 없습니다 [linux - Difference in sites-available vs sites-enabled vs conf.d directories (Nginx)? - Server Fault](https://serverfault.com/questions/527630/difference-in-sites-available-vs-sites-enabled-vs-conf-d-directories-nginx)
- Docker, Kubernetes 환경에서는 심볼릭 링크보다 직접적인 파일 관리가 선호됨

**DevOps 관점:**

- Git으로 상태를 관리하고 CI/CD를 통한 자동화 배포에서는 `conf.d` 접근법이 더 간단합니다 [linux - Difference in sites-available vs sites-enabled vs conf.d directories (Nginx)? - Server Fault](https://serverfault.com/questions/527630/difference-in-sites-available-vs-sites-enabled-vs-conf-d-directories-nginx)
- 파일 이름 변경만으로 사이트 비활성화 가능: `mysite.conf` → `mysite.conf.disabled`

### 🔧 최신 Nginx 설정 구조

### **현재 표준 구조 (2024-2025)**

**1. 기본 nginx.conf 구조:**

```bash
*# /etc/nginx/nginx.conf*
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    *# MIME 타입 설정*
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    
    *# 로그 포맷 설정*
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
    
    *# 성능 최적화*
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    
    *# 추가 설정 파일들 포함*
    include /etc/nginx/conf.d/*.conf;
    
    *# 기본 서버 설정 (이전의 default.conf 내용이 여기 포함됨)*
    server {
        listen 80 default_server;
        listen [::]:80 default_server;
        server_name _;
        root /usr/share/nginx/html;
        
        location / {
            index index.html index.htm;
        }
        
        error_page 404 /404.html;
        location = /404.html {
        }
        
        error_page 500 502 503 504 /50x.html;
        location = /50x.html {
        }
    }
}
```

### **2. 사이트별 설정 파일 생성:**

```bash
*# 새로운 사이트 설정 파일 생성*
sudo nano /etc/nginx/conf.d/mysite.conf
```

```bash
*# /etc/nginx/conf.d/mysite.conf*
server {
    listen 80;
    server_name mysite.com www.mysite.com;
    root /var/www/mysite;
    
    location / {
        index index.html index.htm;
        try_files $uri $uri/ =404;
    }
    
    *# 정적 파일 캐싱*
    location ~* \.(css|js|png|jpg|jpeg|gif|ico|svg)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### **3. 사이트 활성화/비활성화:**

```bash
*# 사이트 비활성화 (파일명 변경)*
sudo mv /etc/nginx/conf.d/mysite.conf /etc/nginx/conf.d/mysite.conf.disabled

*# 사이트 재활성화*
sudo mv /etc/nginx/conf.d/mysite.conf.disabled /etc/nginx/conf.d/mysite.conf

*# 설정 재로딩*
sudo nginx -t && sudo nginx -s reload
```

### 🔧 기본적인 Nginx 문법 해석

최신 Nginx에서는 **기본 server 설정이 nginx.conf 파일 안에 직접 포함**되어 있습니다:

```bash
*# /etc/nginx/nginx.conf (기본 server 블록 부분)*
http {
    *# 전역 HTTP 설정들...*
    
    *# 기본 서버 설정 (이전의 default.conf 내용)*
    server {
        *# 🌐 네트워크 바인딩 설정*
        listen 80 default_server;         *# 기본 서버로 지정*
        listen [::]:80 default_server;    *# IPv6 지원*
        server_name _;                    *# 모든 도메인명 매칭*
        
        *# 📂 파일 시스템 매핑*
        root /usr/share/nginx/html;       *# 웹 루트 디렉토리*
        
        *# 📍 URL 경로별 처리 규칙*
        location / {
            index index.html index.htm;   *# 기본 파일 우선순위*
        }
        
        *# 🚨 에러 페이지 처리*
        error_page 404 /404.html;
        location = /404.html {
        }
        
        error_page 500 502 503 504 /50x.html;
        location = /50x.html {
        }
    }
    
    *# 📁 추가 사이트 설정 파일들 포함*
    include /etc/nginx/conf.d/*.conf;
}
```

### 🛠️ 실제 커스텀 웹사이트 배포 예시

**방법 1: nginx.conf 직접 수정**

```bash
*# 기존 default server 블록을 주석 처리하고 새로운 블록 추가*
server {
    listen 80;
    server_name localhost;
    root /var/www/mysite;              *# 경로 변경!*
    
    location / {
        index index.html index.htm;
    }
}
```

**방법 2: conf.d 디렉토리 활용 (권장)**

```bash
*# 새 사이트 설정 파일 생성*
sudo nano /etc/nginx/conf.d/mysite.conf
```

```bash
*# /etc/nginx/conf.d/mysite.conf*
server {
    listen 80;
    server_name mysite.local;
    root /var/www/mysite;
    
    location / {
        index index.html index.htm;
        try_files $uri $uri/ =404;
    }
}
```

- **주의)** '중괄호(`{...}`) 형태의 구문'과 '세미 콜론(`;`)으로 끝나는 구문' 2가지가 있다. 설정 파일을 작성할 때 세미 콜론(`;`)을 빠트려서 에러가 뜨는 경우가 많으니 주의하자.
